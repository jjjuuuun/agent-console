# Changelog: @agent-console/graph-editor

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). A change that breaks the version
range of an internal dependency bumps the other package's version and is recorded here.

## [Unreleased]
- First fit determinism and node separation (0.2.3): after the editor's first fit it now re-fits once more when `document.fonts.ready` resolves (only if the user has not moved the view and the viewport is still the last fit), and confirms the label layout after every programmatic fit, so the first zoom no longer depends on when the web font arrived (the same team used to open at zoom 0.72 in one theme and 0.86 in the other). New optional prop `nodeSeparation` (flow px, default 0 = off) and pure function `separateNodesVertically`: in a read-only view it pushes a node down when a node above it in the same column, measured at its real height (for example a run result line made it taller), is closer than the gap, so target nodes no longer overlap by 0-2px. The graph data is not changed. Chip text uses `word-break: keep-all`.
- Palette category label (0.2.2): `GraphEditor`, `TeamPalette`, and `NodePalette` take an optional `categoryLabel` (`(category) => string`), and `groupNodeTypes` and `buildTeamPalette` take it as a trailing argument. A palette group is now keyed and colored by the original `category`; only its displayed name (and the group sort order and search) uses the label. `PaletteGroup` gains `label` and `colorKey`. Previously a host that translated `category` itself changed the group color per language, because the color is a hash of the category string. Without `categoryLabel`, behavior is unchanged.
- Palette locale (0.2.1): `NodePalette`, `TeamPalette`, and `GraphEditor` take an optional `locale` (BCP 47, normally the display language) for group/item sorting and case-insensitive search; `groupNodeTypes` and `buildTeamPalette` take it as a trailing argument. The default is `DEFAULT_PALETTE_LOCALE` (`"en"`) instead of a fixed Korean locale. The avatar glyph uses `toUpperCase()` so it does not depend on the host locale.
- Chip folding (0.2.0): when the label layout still has no room after relaxing the gap and the node tolerance, chips fold into an icon and `+N` to take less space (the third fallback step, before covering ports). `LabelSpacing` gained `fold` (default true), `foldedWidth` (44) and `foldedHeight` (26); `SpreadInput` gained `foldable` and `foldedSize`; and there is a pure function `spreadLabelLayout` (positions plus the ids of folded edges; `spreadLabels` returns positions only) and the type `LabelLayout`. The editor passes folding down through `EdgeLabelSpread.folded`, and edge chips render with `data-folded="true"` (the folded and unfolded sizes are measured separately, so chips do not keep folding and unfolding). A folded chip has its full text in `title` and `aria-label`, and the unfolded body floats above it on pointer hover and focus. The selected edge and edges whose label position the user set are not folded. Without folding, the DOM is unchanged (`flow.snapshot`).
- Message data (0.2.0): moved the default messages to `src/locales/ko.json` (`messages`, `shapes`, `layout`; `defaultMessages` is still ko) and added `en.json`. Subpath exports `./locales/ko` and `./locales/en`, the types `GraphEditorLocale` and `ShapeText`, and the public `localizeEdgeShapes` (translates built-in shape names and descriptions). New message `nodeAriaStatus` (the status appended to a node's accessible name). Hard-coded Korean in built-in shapes, the ELK engine and option names, and node accessible names moved into the catalog (same default messages), and the error for an unset `resolvePorts` is now developer English. Added tests that check matching keys and placeholders and that the source has no Korean strings.
- Edge label spacing and port protection as settings (0.2.0): the optional `GraphEditor` prop `labelSpacing` (`LabelSpacing`: `gap` 8 screen px, `minGap` 4 px, `nodeTolerance` 8 flow px of tolerance over node bodies (the old 24 is gone), `portClearance` 4, `minZoom` 0.5, `maxZoom` 1, `settleMs` 200). Gaps are in screen px, so the flow gap = px ÷ zoom (zoom clamped to 0.5–1), and the layout is solved again only once, `settleMs` after zooming ends. Obstacles include port circles plus an outer margin (`portObstacles`, `ObstacleRect.protect`), which is not reduced even in the node tolerance step. Fallback order: gap 8→4 → body tolerance 0→8 → keep ports clear even if more of the body is covered → allow covering ports (last). Zero overlap between labels is never given up. `spreadLabels(inputs, box, obstacles, spacing?, zoom?)` (omitting spacing = the old behavior), and the public `resolveLabelSpacing`, `flowGap` and `LABEL_SPACING_DEFAULTS`. With `createElkEngine({ optionDefaults })` the app passes auto layout option defaults (for example `layerGap`) as data (the library default stays 80). Without the new props and options the DOM snapshot is unchanged (only label positions move to the target gap).
- Connecting from anywhere on a node: drag from the edge band of the selected node (handle id `edge:<side>`, thickness adjusted for zoom) and drop **anywhere on the body** of the other node to connect. The pure functions `resolveEnds` and `inferKindPorts` (`logic/inferPorts.ts`) choose the ports in this order: the port set by the start or end handle → the edge type's `default_ports` → the first compatible port in the node's port list (node types, edge types and port names are not compared). When there are two or more candidate edge types, `EdgeKindDialog` gains a port column (`EdgeKindCandidateInfo.portsText`) so both are chosen at once. You can also start from a port handle and drop on a body (the direction of the start handle decides source and target). An edge made by inference shows a toast (with undo) telling which port it attached to. The handle snap radius went from 20 to 8 px (`CONNECTION_RADIUS`). Messages `edgeKindPorts`, `connectedInferred` and `dropHere`, and `NodeCardProps.edgeBands`. The keyboard alternatives (connecting from port handles, the `T` key) are unchanged.
- Team editor layout: the `canvasActions` slot, a minimap toggle (`onShowMinimapChange`, default size 140x96), an overlay palette (`paletteOverlay`, `paletteOpen`, `onPaletteClose`), `GraphEditorHandle.addNodeAtCenter`, the pure function `centerFreePosition`, and the messages `minimapShow` and `minimapHide`. The bottom view toolbar stays on one line (`nowrap`). Without the new props the render is unchanged (only the default minimap is smaller).
- Automatic edge routes by default: the sixth step of shape resolution, the built-in default, is `auto` (`bezier` when it is not in the registry; manually edited edges with `waypoints`, `bend`, `radius` or `label_*` but no `layout.shape` are read with the previous default `bezier`; `hasManualRoute`, `builtinEdgeShape`, `DEFAULT_EDGE_SHAPE`). Overlapping parallel segments on the same line are pushed 6px apart (`nudgeParallel`, `RouteOptions.nudge`). `createAutoPath` and `DEFAULT_AUTO_PATH_OPTIONS` make the `autoPath` search limits options. The after-the-fact notice became a warning chip that counts the edges passing through nodes, with an [Auto route] action (the props of `EdgeTroubleChip` changed to `count` and `onAutoRoute`; message `troubleOpen` → `troubleAutoRoute`; `troubleHint` has a `{count}` placeholder). It appears even without a tidy engine. `newGraphUi()` (node direction `auto` for new graphs).
- Standalone delegation, loops, conditions and nested teams: the pure functions `resolveEdgeStyle`, `loopRegion`, `closesFlowLoop` and `planConnection`; attribute-based edge styles (color, pattern, icon, default shape `auto`); more edge chips (`edgeExtraChips`, `edgeBadges`, `renderIcon`, 4 plus `+N`, zoom level of detail); loop region highlighting; creating edges that close a loop (disabled rows and a default choice in `EdgeKindDialog.info`); `bindSummaries` (definition binding cards, [Open], `Alt+Enter`); `ui_hints.shape: stacked`; `nodeRunBadges`; palette `DefinitionItem.meta` and `disabledReason`; ELK handling of back edges (`LayoutEdgeInput.back`, `ElkEngineOptions.cycleBreaking`); and moving the view to a new node added from the palette. `checkConnection` allows cycles for `cycle` edge types. `ChipView` gained the optional fields `fullTitle`, `iconName`, `tone` and `dashed`. Without the new props the render is unchanged.
- Edge follow-up: `MultiLayoutPanel` (bulk [Shape ▾], [Reset route] with a confirmation step, and [Direction] for a multiple selection), `ConfigPanelContext.multiLayout` and `LayoutPanels.multi`, `EdgeContextMenu` (right-click on an edge, plus `Shift+F10` or the ContextMenu key), node direction `auto` (`AUTO_DIRECTION`, `isAutoDirection`; derived and not stored), handles on the same side ordered by the position of the other node (`orderByPeer`, `peerOf` of `placeHandles`), real rendered card sizes as automatic route obstacles (`actualNodeSize`), and `LayoutEngineDescriptor.edgeShapeOption` ("auto-route edges too"; `createElkEngine` defaults to `auto`). Public `patchEdgesLayout`, `patchNodesLayout` and `countResettableEdges`. New message keys (`multiLayoutMixed`, `edgeMenu*`, `tidyAutoRoutes`, `nodeLayoutAutoDirectionHint`, `directionLabels.auto`). Graphs without layout render as before.
- Tidy and auto layout: the `layoutEngines` prop, `LayoutEngineDescriptor`/`OptionDecl`, `createElkEngine` (elkjs ~0.12.0 through a dynamic import and a Worker, with the ELK types isolated), `TidyPopover` ([Tidy ▾] and `L`; preview, apply as one `onChange` with reason `auto-layout`, cancel, a 10-second limit, retry on failure, and resetting all edge routes), `detectEdgeTrouble` and `EdgeTroubleChip`, and the `storage`/`storageKeyPrefix`/`troubleHint` props. The layout undo stack compares and restores `Graph.ui.layout` (other `ui` keys keep their current values).
- Node layout: `NodeLayoutPanel` (the [Layout] tab), `R` (cycle direction) and the toolbar [Change direction], moving a port to another side with a 400ms long press on its handle or `Alt`+drag, layout undo with `Ctrl+Z`/`Ctrl+Shift+Z` up to 30 steps (`LayoutHistory`), `auto-layout` in `ChangeReason`, moving waypoints of edges between nodes moved together (`moveNodesWithWaypoints`), `onLayoutPanelsChange` and `ConfigPanelContext.nodeLayout`, and `patchGraphUiLayout` (merges `Graph.ui`). `GraphEditorHandle` and the existing props are unchanged.
- Edge editing: `EdgeLayoutPanel` ("Shape and route" in the edge panel), `EdgeWaypointLayer` (creating, moving and deleting waypoints, automatic straightening, zoom adjustment), dragging label chips, the `S`/`X`/`Enter` keys and a route editing mode (aria-live). `layout` in `ChangeReason`, `ConfigPanelContext.edgeLayout`, `inheritedEdgeShape`, and the public pure functions in `logic/edgeLayoutOps.ts`. The edge accessible name gains the shape and waypoints (only when set).
- Edges: `AcEdge` draws with the resolved shape (the `edgeShapes` and `layoutDefaults` props) and label position (`label_t`, `label_offset`). Without layout the path is the same as before.
- Port sides: a `Position` per port, even spacing on the top and bottom sides, side glyphs and label chips, and `useUpdateNodeInternals` when handle positions change.
- Extra label text comes only from declarative chips (`value_pointer`, `placement: "title"`). Removed reading the edge `config.label` directly.
