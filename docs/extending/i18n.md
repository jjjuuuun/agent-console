# Localization

Screen text is per-language JSON data. For text the server provides (titles and descriptions in settings schemas,
names that modules and extensions provide, the sentences of error and issue codes), the package that owns the text
ships its translations in its own `locales/` folder, and the server collects them and gives them to the web. Adding a
new language or changing one string takes one catalog file, not a code change ([message-catalog](#message-catalog)).

Data that users create (names, descriptions, content) and the content sent to agents (tool descriptions, prompts,
template bodies) are not translated.

## message-catalog

**When to use**: when a package provides fixed text that appears on screen, ship the translations of that text inside
the package. Plugins outside the repository add translations of their own text the same way, and you can also
distribute a catalog for a new language as a package.

**Minimal shape**: `locales/<language code>.json` files inside the package and one entry point line. The entry point
name is the catalog id, and the value is the module that has the `locales/` folder. Each file is a JSON object with
three sections.

- `text`: original server string → translation. The original string itself is the key. If a user changes a default
  value, it no longer equals the original and is not translated.
- `codes`: error or issue code → sentence template. The values of the issue's `details` fill the `{name}`
  placeholders.
- `ns`: web namespace → nested object (leaves are strings). Use it to override web text or to provide the web text of
  a new language.

```toml
[project.entry-points."agent_console.message_catalogs"]
my-plugin = "my_plugin"
```

```python
>>> import json, tempfile
>>> from pathlib import Path
>>> from agent_console_i18n import CatalogSet, folder_catalogs, load_catalog_folder
>>> root = Path(tempfile.mkdtemp())
>>> _ = (root / "en.json").write_text(json.dumps({
...     "text": {"기본 백엔드": "Default backend"},
...     "codes": {"my_plugin.job_failed": "Job {job} failed"},
... }), encoding="utf-8")
>>> package = load_catalog_folder(root, source="my-plugin", origin="package")
>>> user = root / "user"
>>> user.mkdir()
>>> _ = (user / "en.json").write_text(json.dumps({"text": {"기본 백엔드": "Backend"}}), encoding="utf-8")
>>> catalogs = CatalogSet.from_load(package, folder_catalogs([user]))
>>> en = catalogs.translator("en-US")
>>> en.text("기본 백엔드"), en.code("my_plugin.job_failed", {"job": "nightly"})
('Backend', 'Job nightly failed')
>>> en.text("모르는 원문")
'모르는 원문'

```

**Rules**
- The merge order is package catalogs (in entry point name order) → user folders (in list order), and later ones win.
  `ns` is merged leaf by leaf. An empty string value means "not translated yet" and does not erase the value from an
  earlier source.
- The lookup order is the chosen language → the fallback language → the original server text. Language matching
  starts from the exact code and drops trailing subtags one at a time (`en-US` → `en`).
- The placeholders in a code template must be `details` keys of whatever emits that code. When a value is missing,
  the original server text is shown. When you add a format name, as in `{label, particle.object}`, the web format
  registry applies it.
- A language shipped in a package must have the same keys and placeholders as the base language
  (`compare_catalogs`). A language a user adds may be partial.
- Unreadable files, invalid entries, and modules that cannot be loaded are skipped and recorded as problems
  (`CatalogIssue`, codes `i18n.*`). The other catalogs are still used.

**Common mistakes**: putting user data (team names and so on) in `text` (a name that happens to match gets
translated), translating content sent to agents (it changes model behavior), and distributing without the `locales/`
folder in the package data (`i18n.locales_missing`).

**Turning off**: when you turn off that catalog id in the server settings, only that package's translations drop out
and the original text shows. When the text feature is off, the web uses only its own catalogs and server text stays
as the original.

<!-- extdocs:facts message-catalog -->
- Registration: Register in the entry point group `agent_console.message_catalogs` (constant `agent_console_i18n:MESSAGE_CATALOGS_GROUP`). The registration name is the id.
- Interface:
  - `agent_console_i18n:read_catalog` — Turn a JSON value (already parsed) into a catalog.
  - `agent_console_i18n:package_catalogs` — Read the package catalogs registered through entry points, in name order.
  - `agent_console_i18n:CatalogSet` — Catalogs collected per language. Insertion order is merge order (later wins).
- Built-in implementations: —
- Examples:
  - snippet: Register a package that has `locales/<lang>.json` as an entry point
  - contract-tests: `agent_console_i18n.testing:make_catalog_package`, `agent_console_i18n.testing:make_distribution`
- Turning it off or removing it: Add the name to the setting `plugins.disabled`, or uninstall the package, then restart the server.
